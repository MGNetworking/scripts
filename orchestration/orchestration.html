Création des tâches

Du besoin au backlog (décision 49)
L'utilisateur exprime un besoin, en langage normal — pas une commande
↓

Besoin et cadrage session · boucle de réflexion

  • Lit le CADRAGE.md du grand dossier, le README, decisions.md, les scripts voisins
  • Confronte au contrat, propose : déjà couvert, correction, ajout compatible, nouveau script ; incompatible → nouveau script, ancien déprécié
  • Pose les choix ouverts en une seule série
  • L'utilisateur seul valide : cadrage mis à jour et daté
↓ seulement alors

La session applique /atomiser Opus

  • Découpe en lots si plus de 7 scripts
  • Lance le rédacteur, avec le cadrage et les identifiants libres
↓

Rédacteur-tache sous-agent · modèle hérité

  • Une fiche par script dans tasks/pending/, backlog à jour
  • Refuse une fiche hors du contrat validé ; n'invente aucune décision
↓

Tâches créées

  • Statut pending (dépendance ou choix en attente) ou ready
  • Ordre : lecture seule → modifie → destructif
  • Backlog et prochain identifiant libre à jour
2

Lancement d'une tâche

Préparation et activation
L'utilisateur lance une tâche, ou la session enchaîne seule
/tache TASK-XXX
↓

Session Claude Code orchestrateur · Opus, qui dure

  • Crée un conducteur-tache neuf : « préparer »
  • Ne garde que ses réponses courtes (30 lignes)
  • Reprend le même conducteur par SendMessage
↓

Conducteur-tache sous-agent · Opus

  1. Charge le contexte : fiche, regles.md
  2. Vérifie : ready, dépendances closes, Docker, arbre Git propre, fiche dans le cadrage — sinon REFUS
  3. Active la tâche : pending → active, backlog, 1 commit
Rend PRÊTE + la commande de lancement
↓

Étape 4 — la session lance l'agent

En arrière-plan : l'agent peut tourner une heure, un sous-agent ne peut pas l'attendre.
# lancé par la session, en arrière-plan bash orchestration/outils/lancer-agent.sh \ <agent> TASK-XXX [fichier de retours]
Fiche agent: orchestrateur : pas d'agent ; le conducteur écrit lui-même sur agent/TASK-XXX et conduit les étapes 1 à 8 d'un trait.
3

Exécution et validation

L'agent produit, le conducteur vérifie et fait relire

Agent exécutant Claude Code CLI + modèle de la fiche

  • Copie isolée ../script-agents/TASK-XXX, branche agent/TASK-XXX
  • Écrit le script et son fichier de cas
  • Lance le juge, corrige (3 passages au plus), commite
  • Rend une ligne VERDICT à la session
↓

Juge juger.sh, sans modèle

  • shellcheck ; tests dans un conteneur Docker jetable
  • Règles transverses ; signal de longueur (150 lignes)
  • Refuse un faux binaire écrit à travers un lien
↓ Succès : VERDICT → session → conducteur
↺ Échec : l'agent corrige (max 3 passages)

Conducteur — 5. Vérifier

  • Juge relancé, périmètre, assertions jamais en baisse, longueur, validations
  • Sondes, mutations, stabilité (pratique non prescrite, A128)
  • Périmètre débordé ou tests affaiblis → BLOQUÉE
↓ le conducteur lance le relecteur

Relecteur — 6. Relire Opus, lecture seule

  • Critères un par un ; périmètre, conventions ; hors cadrage = BLOQUANT
  • Défauts BLOQUANT / MAJEUR / MINEUR ; tests creux
  • Rend un verdict factuel au conducteur
↓ OK
Défauts : le conducteur écrit le fichier de retours → RELANCER → la session relance l'agent une seule fois → étape 5 refaite, sans seconde relecture

Travail validé

Script et tests conformes : prêt pour la clôture. Sinon, le conducteur termine lui-même ou bloque.
4

Clôture et intégration

Retour dans le dépôt principal

Conducteur — 7. Rendre compte

  • Rapport tasks/reports/TASK-XXX-report.md, compte rendu en tête
  • Chaque réserve → ligne Axx du registre unique TASK-039
  • Écart d'agent ou d'architecture → fiche TASK (décision 46)
↓

Conducteur — 8. Clore

  • Fusion --no-ff de agent/TASK-XXX, copie et branche supprimées
  • Fiche vers tasks/completed/, README, backlog
  • Tâches débloquées → ready
  • Journal, agents.tsv, verifier-liens.sh, commit
  • Rend CLOSE + la tâche suivante
↓

Session — 9. Résumer et enchaîner

  • Mesure du conducteur, commit séparé
  • Push de master groupé en fin de domaine
  • Conducteur neuf pour la tâche suivante
↓

Tâche terminée

Fiche completed, rapport, mesures ; copie supprimée (gardée si blocked)

Mode automatique

La session enchaîne la tâche ready suivante avec un nouveau conducteur, sans message de l'utilisateur.

Mode manuel

La session attend une consigne de l'utilisateur.

BESOIN_USER

Décision non tranchée : la session pose la question, la boucle s'arrête.

Contraintes et règles

  • regles.md — droits, commandes, périmètre, arrêt
  • decisions.md — décisions en vigueur, numérotées
  • limites.json — droits techniques de l'agent
  • .claude/settings.json — permissions Claude Code
  • Aucun secret dans le dépôt, aucun config/*.env lu par l'agent
  • Aucune exécution sur l'hôte : tests en conteneur Docker
  • Agent : ni push, ni merge, ni web, ni sous-agents ; n'écrit pas tasks/ docs/ lib/ orchestration/ .claude/ ni les README
  • Une seule relecture, une seule relance de l'agent
  • Aucune fiche hors du CADRAGE.md validé par l'utilisateur
  • Registre unique des anomalies : tasks/pending/TASK-039.md
  • Arrêt : aucune tâche ready, blocked, BESOIN_USER, mode manuel
